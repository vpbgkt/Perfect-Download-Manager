# Publishing the PDM extension to the Chrome Web Store

Everything you need to submit the extension: how to package it, what to paste into each field
on the developer console, permission justifications, privacy disclosures, and the post-approval
steps to wire the store-assigned extension ID into the PDM installer.

The same package works on Microsoft Edge Add-ons; see the [Edge section](#microsoft-edge-add-ons)
at the bottom.

## 1. Package the extension

Run the pack script from the repo root:

```powershell
./build/pack-extension.ps1
```

This produces `dist/pdm-extension-<version>.zip` (the version is read from `manifest.json`, so it
tracks whatever you bumped it to). It sanity-checks that all icons and required files are present,
and packs them at the root of the archive (Chrome Web Store rejects zips that contain a top-level
folder).

> Icons are generated by `./build/make-icons.ps1`, which renders the official PDM app logo
> (`src/PDM.App/Assets/pdm.ico`) to 16/32/48/128 px PNGs so the extension matches the desktop
> app. Re-run it after changing the app icon.

## 2. Upload

1. Open [chrome.google.com/webstore/devconsole](https://chrome.google.com/webstore/devconsole).
   (Requires a one-time $5 developer registration fee, which you already paid.)
2. Click **New item**.
3. Drop the zip from `dist/` onto the upload area.
4. When it finishes, you land on the store listing form. All the tabs on the left
   (Store listing, Privacy practices, Distribution) must be green before you can submit.

### Description (paste in the Description field)

> Keep this in sync with actual behaviour. Auto-interception has been **on by default** since 1.2.x,
> and since 1.3.0 the extension no longer breaks downloads when the desktop app is absent. A listing
> that contradicts the shipped defaults is both a review risk and a support burden.

```
Perfect Download Manager Integration hands off downloads from Chrome to Perfect Download Manager (PDM), a free Windows download manager that splits every file into multiple parallel connections, resumes interrupted downloads reliably, and organises everything by type.

What this extension does
- Automatically hands your browser's downloads to PDM. This is on by default and you can turn it off at any time from the popup or the Settings page.
- Adds a "Download with PDM" right-click menu on every link, image, video and audio element.
- Popup toolbar button with a one-click "Send this page to PDM", a live connection indicator, and a "Scan page for media & links" tool that lists every downloadable file and video on the current page so you can send one or all of them to PDM.
- A keyboard shortcut (Alt+Shift+P by default) to send the current tab to PDM.
- Smart filtering: small files that gain nothing from a download manager (PDFs, Office documents, images) stay in the browser by default. One toggle sends everything to PDM instead.
- Sends the download URL, referrer, and suggested filename to the PDM desktop app over a secure local channel (Chrome Native Messaging + a per-user Windows named pipe). Nothing is sent to any remote server by the extension.

Works before you install the desktop app
- The download engine is the free PDM app for Windows. If it isn't installed yet, this extension does not break your downloads: it detects that the app is missing and leaves the download to your browser, untouched. You'll see a setup page explaining how to install PDM whenever you want the faster engine.
- No download is ever lost. If a handoff to PDM fails for any reason, the browser completes the download instead.

Privacy
- The extension never uploads your browsing history, download list, or any personal data to a remote server. Every download URL you send stays on your machine, going only to the local PDM app.
- Your settings are stored locally with chrome.storage.local. No telemetry, no analytics.

Get the desktop app
- https://perfectdownloadmanager.com/#download

Bugs and feedback
- support@perfectdownloadmanager.com
```

## 4. Privacy practices — copy/paste

This section is where extensions live or die in review. Because we do not collect any user
data ourselves, every disclosure below is honest and easy.

### Single purpose
```
Send download URLs from the browser to the Perfect Download Manager desktop app so users can download files faster with multi-connection downloading, pause/resume support, and better organisation than the browser provides on its own.
```

### Permission justifications

**downloads**
```
This is the extension's core function. When the browser starts a download, the extension cancels it and forwards the URL to the Perfect Download Manager desktop app so the file is downloaded with multiple parallel connections instead. The user can turn this off with a toggle in the popup or the Settings page. The permission is also used to complete a download in the browser as a fallback when the desktop app is not installed or a handoff fails, so that no download is ever lost.
```

**nativeMessaging**
```
The extension communicates with the Perfect Download Manager desktop app installed on the same machine via Chrome Native Messaging (host name com.pdm.host). The native host relays the download URL to PDM over a per-user local named pipe. No data leaves the user's machine through this channel.
```

**contextMenus**
```
Adds a "Download with PDM" right-click menu on links, images, audio and video elements so users can send a specific resource to PDM.
```

**notifications**
```
Shows a brief confirmation toast when a download is successfully forwarded to PDM, and warns the user if PDM is not running or reachable.
```

**storage**
```
Stores the user's own settings locally with chrome.storage.local: the auto-intercept toggle, the file-type filters, the notification and fallback preferences, the chosen theme, and whether the setup page has already been shown. No remote storage or synchronisation is used.
```

**activeTab**
```
When the user clicks the extension icon, the popup reads the active tab's URL so it can offer a one-click "Send current tab to PDM" button. activeTab grants temporary access to the tab only in response to the user's click; the extension never reads tab URLs in the background.
```

**scripting**
```
Used only for the popup's "Scan page for media & links" button. When the user clicks it, the extension runs a small script in the active tab (granted temporarily by activeTab) to collect the URLs of downloadable file links and video/audio sources on that page, then lists them so the user can choose which to send to PDM. It never injects scripts automatically or in the background; injection only happens in direct response to the user's click.
```

## 6. Submit for review

Click **Submit for review**. Turnaround is usually 1–3 business days for a new extension
that requests `nativeMessaging`. Extensions with only `activeTab`-scoped permissions tend to
clear review faster than those with broad host permissions, which is why we dropped
`http://*/*` and `https://*/*` in this manifest.

## 7. Post-approval — wiring the store ID into PDM (DONE)

The extension is published. Its permanent Chrome Web Store ID is:

```
phbbcmofdbbojilmcpaghnafpamnocom
```

Listing: https://chromewebstore.google.com/detail/phbbcmofdbbojilmcpaghnafpamnocom

Everyone who installs from the store gets that same ID, and PDM is already wired to it. The
following are all committed in the codebase — you only need to **ship a new PDM release** so
users get them:

1. **App auto-authorises the store ID on every launch.**
   `App.StartBrowserListener()` calls `NativeHostRegistrar.EnsureStoreExtensionRegistered(...)`,
   which writes the native-host manifest (`%LOCALAPPDATA%\PerfectDownloadManager\native-host\com.pdm.host.json`)
   with `chrome-extension://phbbcmofdbbojilmcpaghnafpamnocom/` in `allowed_origins` and the
   per-user registry keys for Chrome/Edge/Brave. It merges rather than overwrites, so a
   sideloaded dev ID a user added stays authorised. Result: install from the store → it just
   works, no sideloading, no ID pasting.

2. **The store ID is the default in the registration script.**
   `browser-extension/install-native-host.ps1` defaults `-ExtensionIds` to the store ID.

3. **Browser Setup opens the store listing.**
   `BrowserSetupViewModel.StoreUrlFor(...)` returns the Chrome Web Store URL and
   `OpenStorePage` launches it in the selected browser. The wizard also reflects "Configured."
   automatically because `EnsureStoreExtensionRegistered` already registered the ID.

The `WebStoreExtensionId` / `WebStoreListingUrl` constants live in
`src/PDM.App/Services/NativeHostRegistrar.cs` — update them there if the ID ever changes
(e.g. an Edge Add-ons listing gets a different ID; add it alongside the Chrome one).

## Microsoft Edge Add-ons

Edge accepts the same zip package. Steps:

1. Register once at [partner.microsoft.com/dashboard/microsoftedge](https://partner.microsoft.com/dashboard/microsoftedge).
2. Register a new extension, upload the same zip from `dist/`, and paste the same listing text.
3. Edge assigns a different permanent extension ID. Add it to `allowed_origins` in the
   native host manifest alongside the Chrome Web Store ID.

## Bumping the extension for future updates

- Increment `version` in `browser-extension/chromium/manifest.json` (Chrome Web Store
  requires a strictly higher version for every uploaded zip).
- Run `node --test --test-force-exit browser-extension/tests/background.test.js`. This is the gate
  on the interception logic — in particular that the download is cancelled before Chromium's
  filename barrier is released, and that no download is lost when the native host is missing.
- Run `./build/pack-extension.ps1` to produce a new `dist/pdm-extension-X.Y.Z.zip`.
- Re-read the listing description and the **downloads** permission justification against the shipped
  defaults. Reviewers compare them, and the defaults have changed twice now.
- On the dashboard, open the existing item, upload the new zip under **Package**, hit
  **Submit for review**. Subsequent updates usually clear review in hours.

### Manual smoke test before submitting

Automated tests stub the `chrome` API, so they cannot prove Chromium's real pipeline behaves as
expected. Load the unpacked extension and check these by hand:

1. **The dialog fix.** Enable `chrome://settings` → Downloads → **Ask where to save each file before
   downloading**. Download a large file. PDM should take it and **no save dialog should appear**.
   Repeat immediately after a browser restart, which is when the service worker is coldest.
2. **Same, in Edge and Brave.** They ship different Chromium builds and Brave was the browser where
   the leaked dialog was originally reported.
3. **Keep-both mode.** Turn off "Cancel the browser's own download after handoff". The dialog *should*
   appear — that setting means the browser is downloading too.
4. **No desktop app.** Unregister the host
   (`./browser-extension/install-native-host.ps1 -HostExe x -Uninstall`) and restart the browser.
   A download must complete normally in the browser, the badge must go amber, the setup page must
   open once, and the popup must show "Not installed" with the setup card.
5. **Install mid-session.** With the host still unregistered, re-register it and restart the browser,
   then hit **Re-check** on the setup page. It must flip to "You're all set".
6. **Cold start.** Close PDM entirely, then download something. The extension must show
   "Starting…" rather than "Not installed", and must not produce a duplicate browser download when
   PDM finishes launching.
